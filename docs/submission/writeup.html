3. Architecture on TrueForge

The VS Code-compatible extension is a client of local TrueForge: the TypeScript SDK creates sessions and streams turns; HTTP registers agent definitions and the local editor MCP server. It never calls model providers directly. TrueForge decides which tools to invoke and pauses edit/write/command calls for approval. Anvil opens an in-editor diff, records decisions per hunk, and lets the MCP handler apply only the reviewed proposal. A journal supports undo and detects subsequent file changes.

The coder agent uses a context-scout subagent for focused discovery, returning file ranges and reasons to the main thread. Deferred tool loading keeps occasional tools out of the initial prompt. Compaction is configured for long sessions. Streaming and Stop/Escape are driven by TrueForge events and cancellation; reviewed file changes commit as individual editor operations. An already committed, accepted change remains undoable when a later step is cancelled.

4. How context is selected

A first-turn repository map is ranked by query relevance and import connectivity, with a default budget of approximately 1,200 tokens. Explicit @file and @symbol mentions add selected code or outlines. The retrieve_context MCP tool combines BM25F lexical ranking (path ×2.5, symbol ×3, comments ×1.2, body ×1), symbol matches, import links, and source/test/documentation pairing. Retrieval defaults to an estimated 4,000-token ceiling per call, configurable up to 5,500. Rendering overhead is charged to the same estimate; it uses characters/3.8 rather than a provider tokenizer.

Every admitted file has a usable range or outline before extra chunks consume the remaining budget. A visible context card explains selected paths, reasons, scores, and omissions. This avoids embeddings and provider dependencies, but Python-oriented parsing and lexical matching can miss cross-language or conceptual relationships. Separate tool calls and explicit mentions are not a single global session budget.

8. Known limitations and what you would do with another month

One workspace folder is used per editor window. Undo history is in memory and does not survive reload. Approved shell commands are not sandboxed and can modify files independently of diff review. Format-on-save or other save participants may change content beyond the proposed text; these changes are captured in the journal. Cancellation prevents uncommitted proposals; it does not roll back earlier accepted edits or arbitrary shell-command side effects. Model tool quality, service availability, and quota affect task completion.

Real editor smoke tests passed in Antigravity IDE 1.107.0. A’s behavior, selection boundary, and undo passed; C passed with 1s/2s retries, automatic fallback, rejection, and clean git status. B’s generated changes passed 61 CLI tests, help, JSON/default serialization, masking, and the three-file check, but the agent turn was cancelled before its final summary after about 29 minutes. A complete four-minute live recording is not yet verified. Free capacity and latency are substantial constraints. Another month would add durable recovery, language-server-backed cross-language retrieval, tokenizers matched to each model, broader remote/Windows editor coverage, and stricter command isolation. Standard VS Code should be tested separately before claiming it was verified there.
